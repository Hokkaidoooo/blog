先看题。

> 下列指令中，执行后**有可能**按存放顺序执行其下一条指令的是（ ）。
>
> Ⅰ. 条件跳转指令　　Ⅱ. 过程调用指令　　Ⅲ. 陷阱（Trap）指令　　Ⅳ. 过程返回指令
>
> A. 仅Ⅰ、Ⅱ　　B. 仅Ⅰ、Ⅳ　　C. 仅Ⅱ、Ⅲ　　D. 仅Ⅲ、Ⅳ

答案是 **A（仅Ⅰ、Ⅱ）**。

这道题看着像背结论，其实只考一件事：**指令在执行阶段究竟往 $PC$ 里写了哪个地址**。抓住这一条，四个条目全能推出来，不需要记任何口诀。

---

## 一、先把题干翻译成一个地址等式

设当前指令存放在主存地址 $A$ 处，自身占 $L$ 字节。取指阶段硬件必然先做一次自增：

$$
PC \leftarrow A + L
$$

于是有两个地址要分清：

- **按存放顺序的下一条指令**：地址恒为 $A + L$，由指令在主存中的物理位置决定，是**空间**概念；
- **按执行顺序的下一条指令**：地址等于该指令执行阶段最终写进 $PC$ 的值，是**时间**概念。

两者相等就是顺序执行，不相等就是程序控制流的转移。所以这道题的全部工作只有一件——判断四个条目的 $PC$ 新值**有没有可能**等于 $A + L$：

$$
PC_{\text{new}} \stackrel{?}{=} A + L
$$

判据只有一句话：**别看指令叫什么名字，看它执行阶段往 $PC$ 里写的是谁。**

---

## 二、四条逐一推演

### Ⅰ. 条件跳转指令：能

用寄存器传输语言写一遍：

1. 取指：取出指令，硬件令 $PC \leftarrow A + L$；
2. 执行：算条件。条件**不成立**时 $PC$ 不动，下一条执行的正是 $A + L$ 处那条；条件成立时 $PC \leftarrow (A + L) + \text{offset}$。

题干问的是"有可能"。条件不成立这个分支实实在在存在，所以 **Ⅰ 有可能**，Ⅰ入选。

顺手排除：含 Ⅲ 的选项只有 C、D，后面只要再确认 Ⅲ 不成立，就能把范围压到 A、B。

### Ⅱ. 过程调用指令：也能

`call` 的执行阶段做两件事：把返回地址 $A + L$ 压栈（或写入链接寄存器 `ra`），再把指令里给出的目标地址装进 $PC$。

关键在于：**目标地址来自指令字面，它完全可以等于 $A + L$。** 两种常见情形：

- 被调用子程序的第一条指令恰好紧挨着 `call` 存放，入口就是 $A + L$；
- 显式写一条偏移量为 $0$ 的调用。

第二种不是纸上谈兵。32 位位置无关代码（PIC）需要取"当前指令地址"，而 x86-32 没有直接读 `EIP` 的指令，手写汇编里就用这个技巧：

```text
call 1f          ; 机器码 E8 00 00 00 00，偏移量为 0
1:  pop  %ebx    ; %ebx 拿到当前 PC
```

`call` 把下一条指令地址压栈，然后跳转到紧邻的下一条指令，`pop` 再把它读进通用寄存器。**`call` 执行后紧接着执行的，正是按存放顺序紧邻它的那条指令。** 所以 Ⅱ 也"有可能"，Ⅱ入选。

### Ⅲ. 陷阱（Trap）指令：不能

陷阱指令（`syscall`、`int n`、`ecall`）是用户程序**显式写出来的同步内中断**。执行阶段硬件做三件事：

1. 把断点 $A + L$ 与程序状态字 `PSW` 保存到内核栈或特权寄存器（如 `sepc`、`EPC`）；
2. 把 CPU 从用户态切换到内核态；
3. 查中断向量表，把**内核空间中陷阱处理程序的入口** $A_{\text{handler}}$ 装进 $PC$。

用户程序在用户空间，处理程序在内核空间，$A_{\text{handler}} \neq A + L$。所以陷阱指令执行完的那一拍，$PC$ 指向的是内核处理程序的第一条指令，**绝不可能是用户空间里 $A + L$ 处那条**。

这里是最容易想错的地方：陷阱**处理结束**之后，确实会靠 `iret` / `sret` 回到 $A + L$。但那是很久以后的事，不是"该指令执行后"的下一拍。

### Ⅳ. 过程返回指令：不能

`ret` 从栈顶弹出当初 `call` 存下的返回地址：

$$
PC_{\text{new}} = RA = A_{\text{call}} + L_{\text{call}}
$$

而 `ret` 自己按存放顺序的下一条是 $A_{\text{ret}} + L_{\text{ret}}$。要"顺序执行自己的下一条"，必须满足

$$
A_{\text{call}} + L_{\text{call}} = A_{\text{ret}} + L_{\text{ret}}
$$

可 `call` 和 `ret` 是主存里两条互不重叠的指令，地址区间 $[A_{\text{call}},\ A_{\text{call}} + L_{\text{call}})$ 与 $[A_{\text{ret}},\ A_{\text{ret}} + L_{\text{ret}})$ 不可能相接相等，等式恒不成立。

哪怕被调过程是个只有一行 `ret` 的空函数、且紧挨着 `call` 存放，`ret` 返回的也是那个 `call` 的下一条，**不是 `ret` 自己的下一条**。

## 三、空间顺序与时间顺序的一张图

```text
主存 .text（地址自上而下递增；每一行都是按存放顺序相邻的指令）

0x00401000  beq  $t0, $t1, Label      ← Ⅰ 条件跳转
0x00401004  add  $t2, $t2, 1            条件不成立：PC = 0x00401004，顺序执行
0x00401020  call $+5                   ← Ⅱ 过程调用（目标恰是自己的下一条）
0x00401025  pop  %ebx                   压栈 0x00401025，再跳到 0x00401025
0x00401050  call FuncQ                 ← 正常调用
0x00401055  mov  %eax, %ecx             返回地址在这里（RA = 0x00401055）
0x00402010  ret                        ← Ⅳ 过程返回
0x00402011  sub  %esp, 4                 ret 绝不会跳到这里
0x00403000  syscall                    ← Ⅲ 陷阱指令（保存断点 0x00403004）
0x00403004  and  $t0, $t0, 0             也不是 trap 的下一拍

0x00403000 执行的那一拍，CPU 已经切到内核态：
0x80000180  [Trap Handler 入口]        ← trap 真正要去的下一条
0x80000240  iret                       ← 处理结束后，才回到 0x00403004
```

把这张图和第二节对照着看：**"下一条"有三个不同的地址**——顺序后继 $A + L$、调用/跳转的目标、以及处理流程结束后的返回点。题干问的永远只是第一个。

## 四、四类指令汇总

| 指令 | 执行阶段 $PC$ 的写法 | 保存返回地址 | 特权级 | 能否执行 $A + L$ |
| :--- | :--- | :--- | :--- | :--- |
| 条件跳转 | 不跳：$A + L$；跳：$(A + L) + \text{offset}$ | 否 | 不变 | **能**（不跳转，或偏移量为 0） |
| 过程调用 | $A_{\text{target}}$ | 是，存入用户栈或 `ra` | 不变 | **能**（$A_{\text{target}} = A + L$） |
| 陷阱指令 | $A_{\text{kernel\_handler}}$ | 是，存入内核栈或 `EPC` | 用户态 → 内核态 | **不能** |
| 过程返回 | $RA = A_{\text{call}} + L_{\text{call}}$ | 否（消耗栈顶或 `ra`） | 不变 | **不能** |

## 五、两个最常踩的坑

**坑一：把"指令执行完的瞬间"和"处理流程结束后的瞬间"混为一谈。**

误选 Ⅲ 的理由通常是："陷阱指令不是要返回下一条指令吗？"——那是 `iret` 干的事，不是陷阱指令本身执行完的事。如果题干问的是"处理流程结束后回到哪里"，那 Ⅱ 和 Ⅲ 都成立，可四个选项里根本没有这个组合。**选项本身就在提示：题干问的是单条指令执行完的直接后继。**

**坑二：把代词"其"换成了别人。**

误选 Ⅳ 的理由是："`ret` 之后确实顺序执行了 `call` 的下一条。"但题干写的是"按存放顺序执行**其**下一条指令"，"其"指当前执行的这条指令自己。对 `ret` 而言，"其下一条"是内存里紧挨着 `ret` 的那条（$A_{\text{ret}} + L_{\text{ret}}$），不是紧挨着 `call` 的那条。

## 六、横向对比：过程调用、陷阱、故障与中断

这一节是组成原理与操作系统的交叉高频区，四类事件的"下一拍"和"返回点"要一次记清：

| 对比维度 | 过程调用 `call` | 陷阱 / 系统调用 | 故障类异常（如缺页） | 外部中断（时钟 / I/O） |
| :--- | :--- | :--- | :--- | :--- |
| 触发方式 | 同步，程序显式调用 | 同步，程序显式执行自陷指令 | 同步，当前指令执行出错被动触发 | **异步**，外部硬件随机信号 |
| 特权级 | 不变 | 用户态 → 内核态 | 用户态 → 内核态 | 转入内核态 |
| 下一拍去哪 | 目标子程序入口 | OS 陷阱处理程序入口 | OS 故障处理程序入口 | OS 中断服务程序入口 |
| 处理完回到哪 | `call` 的下一条 | `trap` 的下一条 | **引发故障的当前指令本身**（重执行） | 被打断指令的下一条 |

注意故障和中断的区别：缺页异常恢复后要**重新执行**触发缺页的那条访存指令，而不是它的下一条——这一条在真题里被反复考过。

## 七、举一反三

**变式一：只改时间节点。**

> 下列事件或指令所触发的处理流程结束并返回用户程序后，会从触发点按存放顺序的下一条指令继续执行的是（ ）：Ⅰ. 过程调用　Ⅱ. 陷阱指令　Ⅲ. 缺页故障　Ⅳ. 除数为 0 故障

答案 **Ⅰ、Ⅱ**。过程调用和陷阱处理完都回到触发点的下一条；缺页故障恢复后重执行当前指令；除 0 会直接终止进程，谈不上"下一条"。同一批指令，问的时间点一换，答案就翻过来。

**变式二：把断点保存位置和流水线预测掺进来。**

> 在支持虚拟存储与流水线的系统中，CPU 在用户态执行指令 $I_k$（地址 $A_k$，字长 4B）。Ⅰ. 若 $I_k$ 是无条件相对跳转且偏移量全 0，则执行后继续执行 $A_k + 4$；Ⅱ. 若 $I_k$ 是 `lw` 且触发缺页，则异常处理完执行 $A_k + 4$；Ⅲ. 若 $I_k$ 是 `syscall`，则执行阶段硬件把 $A_k + 4$ 压入**用户栈**；Ⅳ. 若 $I_k$ 是条件分支，流水线采用"静态预测不跳转"，条件不满足时不产生控制冒险阻塞。

答案 **B（仅Ⅰ、Ⅳ）**。Ⅰ：取指后 $(PC) = A_k + 4$，偏移为 0 时目标就是 $A_k + 4$。Ⅱ：缺页是故障，断点是 $A_k$，要重执行。Ⅲ：断点只能进内核栈或特权寄存器，进用户栈等于让用户程序篡改返回地址。Ⅳ：静态预测不跳转时顺序预取的指令本来就没取错，不必冲刷流水线。

## 八、为什么指令集会长出这四种花样

最后补一层"所以然"。

早期机器只有带自增的计数器 $PC \leftarrow PC + L$，程序在内存里一维线性排列。但工程上立刻要三样东西：**条件决策**（分支循环）、**代码复用**（子程序）、**受保护的资源访问**（内核服务）。

- 只有 `jmp` 实现不了函数复用与递归：同一个子程序可能被 100 处调用，跳回去时该回哪一处？固定单元存返回地址会被递归覆盖——于是有了 `call` / `ret` 加运行时栈，代价是压栈出栈的访存周期。
- 用户程序直接用 `call` 调内核函数则既不安全也不稳定：用户得知道内核地址，且普通 `call` 不切换特权级。于是有了陷阱指令，代价是保存 `PSW`、切态、查向量表、清空流水线的一次性高开销。
- 这四种指令都会打断预取的连续性，引发**控制冒险**。现代处理器为此付出大量芯片面积做分支预测器（BPU）、分支目标缓冲器（BTB）和返回地址栈（RAS）——`call` 压 RAS、`ret` 弹 RAS，返回地址才猜得准。

## 九、速记

- **条件跳转**：看条件，不跳即顺序；
- **过程调用**：看目标，目标可以是下一条；
- **陷阱指令**：入内核，下一拍必是处理程序；
- **过程返回**：回调用点，绝不是自己的下一条。

考场上遇到这类题，别凭中文语感猜。在草稿纸上写下 $A + L$ 与 $PC_{\text{new}}$，问一句"这两个地址有没有可能相等"，答案就定了。
